# V100 FP16 audit

The current trainer does not enable FP16 on Volta: `autocast_for()` only selects
BF16-capable CUDA devices and otherwise runs without autocast. A pure
`model.half()` conversion is therefore not a supported training mode yet.

The first deterministic hazard is in the action codec. Illegal actions were
masked with `-1e9` before `log_softmax`; that value is not representable in
FP16. The codec now promotes the two logits tensors to FP32 at this boundary.
The model's matrix multiplications can still run in FP16, while probabilities,
KL and PPO ratios remain stable.

Other sensitive operations that must remain FP32 are:

- `log_softmax`, categorical log-probability and `exp(logp - old_logp)`;
- GAE, returns, advantage normalization and value loss;
- Card/Tile KL and gradient norm checks.

V100 validation must use FP16 autocast plus dynamic loss scaling for the Actor
and Critic. A full FP16 optimizer without loss scaling is not accepted for a
long run because overflow/underflow can silently corrupt Adam state. The
validation gate is two single-GPU updates with finite loss/KL, initial log-prob
error below `1e-3`, no non-finite gradients, and stable checkpoint reload.

## RTX 4090 conversion probe (2026-11-07)

The real V2 model path was exercised with a small V2 configuration on the local
RTX 4090 (CUDA 12.4, PyTorch 2.6). Direct `model.half()` initially failed in
the V2 tile head because the configured FP32 tile branch fed float activations
to half weights. The branch is now conditional on the runtime dtype, so the
native-FP16 forward and backward pass runs.

The next test used native-FP16 parameters with a normal AdamW optimizer. Step 1
was finite; step 2 produced `loss=nan`. This is optimizer-state overflow, not a
forward mask failure. A second test used FP32 master parameters, copied FP16
gradients to the masters, clipped master gradients, stepped AdamW, and copied
the masters back to the FP16 model. Five consecutive steps remained finite and
all model parameters stayed finite.

Conclusion: direct half-parameter AdamW is rejected. Migration must use FP32
master weights (or the standard FP32-parameter/autocast mixed path) before any
long FP16 run. The native model forward path itself is now compatible, but a
full rollout/update acceptance is still required after the master optimizer is
integrated into checkpoint save and restore.
