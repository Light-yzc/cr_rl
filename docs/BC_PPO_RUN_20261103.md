# 119M 多卡组 BC → PPO 初始运行

运行日期：2026-11-03。真实硬件为 Colab Linux / NVIDIA L4；模型 preset 为 `production`，119,541,766 参数、128 帧上下文。训练完成状态和强度结论分开记录。

## 人类数据

固定 [IL_Replay](https://huggingface.co/datasets/VanguardX101/IL_Replay) revision `059d43a02138a34b1b3009cc2acc7630fb99a638`。扫描两个 SHA-256 校验通过的原始分片，共 10,000 场回放；筛选并近似重建 40 场，覆盖 47 种八张卡组合。

- 来源出牌事件 2,712 个，成功重建 2,539 个；平均逐场覆盖率 93.50%，最低 90%。有 143 个不在重建手牌、27 个掩码关闭及其他未重建事件；不把这些缺失当成正确还原。
- 65,854 条原始标签行，65,814 条合法、无标记的监督行，其中 2,495 条出牌。
- 原始客户端状态和游戏版本不可核验；观测来自固定 crforge 的动作重演，原卡牌等级 16 统一为 11。它是近似 warm-start 数据，不是原始游戏内存观测。缺失事件与状态漂移限制数据质量。
- BC 按整场划分训练/验证，排除留出卡组涉及的整场回放；当前训练分区 40,091 行。自然验证小样本之外，最终选择使用全部 352 条留出出牌标签和固定 1,024 条 WAIT 标签。

## 卡组池

从扫描数据按频率提取 32 套候选，并收集 [RoyaleAPI 当日 Popular Decks](https://royaleapi.com/decks/popular) 中 18 套成功读取的完整组合，保留卡牌及进化/英雄槽位、来源 URL 和日期。两个来源的统计时间不同，历史出现频率不代表当天使用率。

50 条候选记录都通过真实模拟器重置和最多 120 个合法决策的短程测试。其中两套同时来自人类数据与排行榜，合并后实际为 **48 种卡组及形态配置：38 种训练、10 种留出**。训练侧对应 36 种八张卡组合，另外两种是相同卡牌的不同进化/英雄形式；留出侧为另外 10 种八张卡组合。默认 `configs/decks.yaml` 已去重，合并的来源记录保留在 provenance 和 source_aliases 中；`configs/decks_eval.yaml` 保存留出池。原三套保留为 `configs/decks_initial3.yaml`。

本次已经启动的 PPO 使用冻结的训练配置，仍保留 40 个来源名称（其中两对是同一套卡牌及形式），实际覆盖 38 套；没有在运行中改变抽样池。运行目录内的 `run_config.json` 和 `data/league_train.yaml` 记录该配置。默认新运行使用去重后的 38 套。

短程兼容测试不等于穷举全部技能交互。三轮短 PPO 也不保证训练池每套卡组都获得充分样本；实际组合和每卡组对局数会记录。

## BC 选择与指标修正

训练四个 epoch，每轮平衡采样 2,048 条标签，微批次 4、梯度累积 4、学习率 3e-5。每轮完整 checkpoint 写入 Drive 后验证 SHA-256。最后一轮保留用于续训，选中的权重另存 `bc_selected.pt`。

早期 version 2 的出牌指标错误地把 WAIT 与单个手牌槽位比较，导致把概率分散到多张手牌的策略误读为“出牌准确率 0”。已修复并加入回归测试：WAIT=0.4、四个槽位总概率=0.6 时，必须判断为出牌。旧指标隐藏，正确复测写回同一个 W&B run 的 `bc_v3/*`。

最终选择第 **4** 个 epoch，全部 352 条留出出牌标签上的结果：

| 指标（版本 3） | 初始化基线 | 选择的 BC |
|---|---:|---:|
| 给定出牌的选卡准确率 | 30.40% | 41.48% |
| 等待/出牌平衡准确率 | 58.74% | 64.80% |
| 出牌召回率 | 84.38% | 61.93% |
| 等待准确率 | 33.11% | 67.68% |
| 精确落点准确率 | 0.57% | 0.85% |
| 落点误差不超过两格 | 3.69% | 5.40% |
| 落点平均曼哈顿距离 | 13.47 格 | 15.29 格 |

选卡和时机的模仿指标改善；落点仍弱，平均距离还变差。不能把这次训练解释为已获得强通用策略。平衡采样也尚未解决自然出牌概率的校准问题。

BC 日志：[W&B z1e6qd0t](https://wandb.ai/weidemingdeguge-test/cr-rl/runs/z1e6qd0t)。

## 迁移、训练和证据

tiny 真实验收已完成 BC、BC 续训、BC 权重初始化 PPO、PPO 续训，包含正常终局。换卡组只重置对应环境，另一局观测和随机种子保持不变。

119M 已完成三轮多卡组 PPO：[W&B e9l4e5jj](https://wandb.ai/weidemingdeguge-test/cr-rl/runs/e9l4e5jj)。共 9,216 条 learner 样本，10 场正常终局，5 胜 5 负，无模拟器故障或截断；峰值 allocated 显存约 7.53 GiB。

KL 早停使每轮只执行 4 个优化器步，总共 12 步，并没有把每轮采样充分训练两遍。最后一轮触发停止的微批次近似 KL 约 0.141，超过目标 0.02；早停不是把 KL 硬限制在阈值内。后续需要调小步长或扩大有效批次并进行对照。原始轨迹显示 learner 实际用到 12 种八张卡组合；本次短运行没有充分训练整个卡组池。

留出评估以固定种子从整个留出池打乱选取三组对阵，每组保持物理卡组及模拟种子相同、交换模型所属席位，共 6 场。PPO 对冻结 BC 得到 **5 胜 1 负**，无故障和截断，6 份原生回放均导出。样本太少，不能据此认定通用强度提升。评估环境补齐 `Arena_L` 回放元数据，修复了终局后导出回放报错。

## 独立验收结果

- Linux / Python 3.13.16 / PyTorch 2.11.0+cu130 / CUDA 13.0 / NVIDIA L4。训练时 W&B SDK 为 0.28.1；面板和最终文件核验使用 0.31.0。
- **26 项测试通过**；Ruff 和 Python 编译检查通过。
- 初始 PPO 快照所有模型权重与所选 BC 完全一致；PPO 权重随后确实改变；PPO 优化器从第 1 步开始，没有继承 BC 的 512 步 Adam 状态。
- 三份原始轨迹通过合法动作、有效样本、终局奖励、bootstrap 和对局边界审计。
- Drive 中 4 份 BC checkpoint 和 3 份 PPO checkpoint 已验证；最新 PPO manifest 的 10 个引用文件逐个读回检查 SHA-256。
- 从 Drive 恢复 119M 到全新目录后，在 GPU 上真实续训：原始第 3 轮恢复为副本第 4 轮，优化器从 12 步增至 13 步；未传入 `--decks`，仍保留原先 40 个来源名称的冻结池，而没有悄悄换成新的 38 项默认池。该副本短更新不计入原训练 run。
- W&B 服务端读回：BC 有 512 条优化器 loss/梯度记录、4 组正确的 `bc_v3` 验证点；PPO 有 12 条 loss/梯度、72 条策略熵、10 条终局胜率记录。诊断文件也已通过服务端列表确认非空。
- 本地已下载人类 NPZ，其 SHA-256 与 GPU 训练 checkpoint 记录一致；无需依赖原临时 VM 才能取得数据。
