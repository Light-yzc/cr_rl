# 真实输入审计与固定小集拟合结果（2026-11-10）

## 本次完成的工作

对当前repaired BC数据的492000行进行流式输入审计，并从checkpoint原训练分区固定抽取64个有真实选择的状态，另取64个原验证分区状态作控制集。每组32个choice-WAIT、32个普通出牌，保留完整128帧同座历史。完整history+time_mask+legal mask哈希在这128状态中未发现重复输入或冲突标签；这不是全数据集的冲突审计。

真实数据先在免费CPU上流式解压/审计，只下载3.66MB样本包和JSON至本地。CPU已释放。使用已有F盘conda环境和本地RTX4090，所有实验脚本、数据、临时文件、缓存、输出均在G盘；没有安装新环境或启动收费GPU。

## 真实输入中的问题

### 超长buff值已确认，不再只是推测

所有真实有效实体共5836615个实体时刻。三列buff_ms的累计标量数17509845，超出FP16最大有限值65504的标量260个，占约0.001485%。分别为buff_ms_0/1/2的126/114/20次。此数不是对局数或帧数，同实体会跨时刻重复。

实际记录：row15292 / replay10 / seat0 / tick3060 / entity7的buff_ms_1原值999999849，除10000并取float32后为99999.984375，与此前frame.entity_in失败日志吻合。另一条buff_ms_2记录为row446382 / replay266 / tick2820。

它确认了数值编码存在极端输入。当前FP32帧编码器保证前向范围，但未证明这种输入的优化条件合理。尚未逐批关联极值与梯度尖峰，不能把稀有极值宣布为所有平台期的唯一根因。

### 更常见的类别字段编码缺口

| 字段 | 真实范围/频率 | 已核实的编码行为 |
|---|---|---|
| queue，4列 | 最大1416；1968000标量中91.35% >100，27.88% >1000 | schema明确为卡牌词表ID，却未进入adapter.card_fields和policy.card_groups，按原始连续数值进入header MLP |
| enemy_play_cast，8列 | 最大1429；3936000标量中73.56% >100，22.41% >1000 | 施放形态词表ID，同样遗漏类别编码 |
| ability_unit，2列 | 最大1111；984000标量中154425个非空 | 是每局任意编号的实体handle，不能按卡牌ID编码；实体id被适配器清零，但header handle仍保留，缺少明确实体关联 |

这不是“模型完全看不到卡牌”：hand_card、enemy_play_card等已有embedding。问题是还有这些原始编号/形态走连续特征通道，带入任意顺序及大尺度。网络有可能学会忽略或利用它们，但当前表示没有提供合适的类别/关系结构。

低优先级项：last_ability_run_refusal有19个值为1006的枚举记录。hp/max_hp最高255.9997属于另一类大数值，需按单位/卡等语义独立核实，不能一并归为非法。

### 数值与内存

- 所有64步完成，退出码0，GradScaler保持32；无非有限loss/梯度。
- 分组梯度均非零，并记录了frame、temporal、WAIT、slot、tile等代表参数实际变化。没有发现整个主干或动作头被冻结/断梯度。
- 最后一步裁剪前梯度范数16.26，clip系数约0.0615；仍有较强裁剪，不能把64步未完全拟合等同于容量不足。
- 运行/评估约201.6秒，不含启动和数据准备；GPU已释放，CUDA峰值约4895MiB。
- 日志观测主内存峰值约2347MiB，结束约1159MiB。模型经meta→GPU逐tensor载入，不创建完整CPU模型副本、不恢复生产optimizer；映射数据/解压缓存已回收。TMP/TEMP、Python/CUDA/Torch缓存均显式在G盘。

## 对“是不是容量/架构不够”的回答

当前模型确实能对固定真实状态学习，尤其能拟合时机差异，梯度和参数更新也正常；这削弱了“模型完全学不动/通路坏了”的解释。训练与控制集出现分化，支持下一步优先检查泛化、表示与监督，而非直接扩容。

但64状态/64步还没有被充分记住，选牌和落点拟合仍不充分。因此该实验不能证明122M容量足够，更不能证明架构完全没问题；它只是指出当前先扩到300M缺少依据。控制集各项统计样本较少（32个出牌），不当作正式泛化强度/胜率评测。

## 推荐下一步

1. 先建立版本化的输入编码对照：queue/enemy_play_cast使用共享词表embedding与有序读出；ability_unit用实体匹配/存在标志；超长buff用超长标志与有界/对数时长，保留未知值语义。不要直接替换旧checkpoint输入。
2. 同一小集、同起始权重/seed对比新旧表示的分头拟合曲线和控制集；同时统一有效batch内条件分母，避免把batch更改混入速度测试。
3. 只有表示和优化检查通过且小集拟合仍明显受限时，再测试更直接的实体→时机/选牌读出或较小/当前模型对照。不要同时换主干、reward、lambda和loss。
4. 任何候选回到正式训练之前，需真实全验证与固定换边实战门禁；本次小集结果不作晋升。
