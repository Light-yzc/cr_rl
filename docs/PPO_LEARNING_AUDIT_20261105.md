## 梯度确实在传播，但“有梯度”不等于方向有效

38–49轮提交Actor140步、Critic1354步；所有记录范数有限，零范数次数均为0。
Actor范数范围2.499–86.233、中位9.056，100%被裁剪；Critic范围.0412–24.494、中位1.395，
81.09%被裁剪。`clip_grad_norm_()`返回的是裁剪前范数，不能把86解释成实际未经保护的更新。
Adam对缩放还有自身自适应，不能把`.5 / norm`直接解释为学习率被缩小了同样倍数。

对完整44→49 checkpoint进行CPU检查，WAIT、选牌、落点、时序主干及Critic的参数确实变化，
相关Adam动量非零；没有发现Actor被冻结、主干整体detach或优化器根本不step。
参数变化本身包含weight decay，技能头就是反例，因此同时检查了Adam矩。
此检查不提供每个策略头的当前梯度范数，也不证明这些变化提高了胜率。

各有效batch的梯度先累计`loss * microbatch样本数`，step前只除以总样本数一次，
没有发现重复除batch导致梯度被错误缩小的实现。BC的class-prior权重不进入PPO损失。

### 用户提出的“早停后减LR”

方向可以测试，但当前实现先前向/反向，在optimizer.step之前检查新batch相对冻结behavior的KL。
若当前参数在这个batch上已经超限，只改LR并重算，当前分布不变，KL仍会超限。
同理，丢弃当前batch梯度不会自动回退此前已改变的参数。该早停属于在新batch上的抽样检测，
不是每次step后对整个rollout保证KL硬上限；50号被拒绝batch的Card KL达到.0671就是例子。
若需要更严格的控制，可单独测试固定choice校验集合的step后KL检查与完整状态回退；
要计入额外前向与重试成本，不能把它当免费增加数据利用。

可以选择两种明确不同的方案：

1. **后续轮次调整Actor LR**：根据提前停止与首遍覆盖记录，下一轮降低LR，例如先对照1e-5；
   有下限、上限与明确调节条件，避免每次早停机械减半直至接近零。这能改善后续轮次覆盖，
   不能追回本轮没更新的数据。Critic LR和KL门限保持。
2. **本轮回退重跑**：保存Actor、完整Adam、shuffle/RNG和梯度累计边界，必要时回退到本轮
   Actor优化起点，以更小LR重放同一冻结rollout；优势/return/reference不重算。
   只回退最后一步不一定使所有后续batch的KL合格，需要明确回退范围。
   限制重试次数和总计算预算，记录所有尝试与最终提交步，不能只恢复权重却保留已推进的Adam矩。

小LR可能带来更多实际Actor优化、增加墙钟；同采样预算不等于同实际计算量。
优先做有界LR对照，再决定是否承担事务式回退的内存、日志和恢复复杂度。

这一小批上，模型有乐观偏差，完整回报误差不优于零预测。它是**采样时的预拟合诊断**，
不是本轮训练后Critic的独立验证，更不能仅凭std小就断言价值幅度坍缩。

训练中平均value_loss只有.0034–.0118（含0.5因子）。能拟合一轮目标与跨局可靠预测是两件事。

旧诊断目标更短、自举更强，44–49轮EV可显示+.15到+.53；同一预测换用真正Critic目标后，
47轮+.307变为−.181、48轮+.153变为−.303。这只是度量目标改变，不是模型突然退化，
也说明为什么监控要标注target lambda。
