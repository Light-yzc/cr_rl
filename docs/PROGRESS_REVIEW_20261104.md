## 模型与训练流程检查

### 1. 当前优先问题是动作时机、落点和数据一致性

当前 BC 将平衡的 WAIT/动作时机损失与条件选牌/落点损失分开，闭环动作频率不保证自然校准。增加 WAIT bias 会同时减少误动作和真正动作窗口的响应概率，不能只看自然 NLL 或总体 WAIT accuracy。

旧数据还存在人类事件与模拟器重建局面的偏差，部分轨迹被截成前缀。Stage 2 已扩大中后期覆盖，但达到 120 秒不等于状态忠实。应按来源、时段、卡组分别验证；尚无证据支持把停滞直接归因于 121M 参数不足。

### 2. 旧落点头缺陷已修，仍需验证当前模型效果

representation-v2 已启用 query 残差、FP32 placement head、二维空间编码，以及实体离散 embedding、动态四查询池化。旧版丢失 query 直达路径、BF16 空间差异被抹平的问题，不应继续描述成当前默认 v2 没修。

当前仍使用每帧汇聚、因果时间 Transformer、条件选牌与落点 cross-attention。合法 mask 在归一化前施加，联合分布构造及相关测试未显示错误；没有发现需要立刻推翻整个架构的证据。测试通过不代表已排除所有训练或泛化缺陷。

### 3. 确认的 V100 适配缺口

`training/separate.py::autocast_for` 与 `scripts/train_bc.py` 只在支持 BF16 时启用混合精度，否则回退 FP32，没有 FP16 + GradScaler 路径。当前 L4 路线不受此项影响，但不能直接沿用 L4 的 batch/显存测量部署到 V100。迁移前须补实现或接受 FP32，并实际测 128 帧前向、反向、优化器和完整采样。

### 4. 两个非阻断的实现注意点

- BC 梯度累积平均的是各微批次损失，末尾不足 batch 的微批次与完整微批次权重相同；条件损失还分别按动作/WAIT/出牌计数归一化。它不等价于拼接 effective batch 后计算一次条件损失。当前不是 NaN 或停训证据，但对比实验应固定采样/微批次设置，若改成按类别计数累积需单独验收。
- v2 历史帧对手牌和卡组 ID 分组做均值池化，不保留这些 ID 在组内的排列；当前动作头仍显式读四个手牌槽位，其他全局特征也会提供信息，因此不能称为“模型不知道手牌”。这是历史表征的压缩取舍，未证明它导致停滞；需要时再做槽位表征消融。
