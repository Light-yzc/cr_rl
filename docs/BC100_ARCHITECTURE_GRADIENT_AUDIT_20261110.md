# BC100 架构、输入与梯度审计（2026-11-10）

## 结论与优先级

本次没有找到“KDA算法不对、全模型断梯度、未来帧泄漏、padding破坏记忆”这样的整体失效证据。现有实现的分块/递推、输入/参数梯度、因果性、padding与reset共22项CPU测试通过。不能据此断定183M模型容量已经够，也不能断定100epoch一定能够收敛。

确认了两个需要区分的问题：

1. **0.4秒离线重采样仍保留0.25秒的`episode_step`计数**，因此BC与真实0.4秒环境的时钟特征关系不同。这是跨环境分布偏移，可能损害实战；单独不能解释同一离线验证集上的平台。
2. **整局forward memory与长程梯度不是一回事。** 当前每32帧（12.8秒）detach全部KDA矩阵和GQA KV。晚动作的loss读得到早期状态，但不能通过早期缓存把梯度传回32帧以前的观测编码器。这是明确的TBPTT训练语义，不是意外断图。

输入编码仍有旧问题，且本次复现了一个更具体的数值机制：超长buff即使使用FP32、输出完全有限，也能使实体汇总注意力更尖锐，并大幅降低输出对其他空间/血量输入的局部敏感度。**有限值不等于优化条件良好。** 但该压力探针没有证明这些稀有帧是整个平台期的主因。

## 范围与证据

- 只读当前`state_policy.py`、`state_temporal.py`、`policy.py`、`observations.py`、重采样及BC训练实现；没有修改生产源码、数据、checkpoint、云端训练或模型超参。
- 全部新文件位于G盘。使用已有F盘conda Torch，仅CPU；未创建运行时、未安装环境、未占用GPU。
- 新探针：`artifacts/bc100_architecture_audit_20261110/probe.py`及`result.json`。总CPU探针约7.6秒，不包括导入。
- 表征探针只构造旧epoch5已训练的实体/header/card-context模块，共7,140,608参数；用Identity factory避免构造旧113M时序主干。完整源checkpoint以mmap只读，未加载Adam或全模型到CPU。
- 输入只流式提取已有128状态包中的8个真实末帧，没有物化完整128×128窗口数组。表征探针使用的是旧epoch5编码器，**不是当前100epoch模型的门控测量**。
- 时序梯度探针使用相同生产算子的32维、6KDA+2GQA随机模型，共64帧。它用于证明计算图语义，不代表已训练183M模型的战术能力。

## 1. 时钟关系存在系统性迁移差异

Java `LadderEnv`每次环境决策增加一次`episodeStep`，每次推进`decisionTicks`个原生tick；导出header时分别写`decision_ticks`、`episode_step`和`tick`。旧记录间隔是5ticks，源状态符合`tick=5×episode_step`。

`resample_game`保留原动作pre-state及其原tick/time_ms，只将header中的`decision_ticks`改8，并另存逻辑ticks。这保护了动作标签身份，却也保留了旧的决策计数。真实样例：

| 源tick | 保留的episode_step | 后移逻辑tick | 原生0.4秒该时刻的step |
|---:|---:|---:|---:|
| 1180 | 236 | 1184 | 148 |
| 2640 | 528 | 2640 | 330 |
| 5630 | 1126 | 5632 | 704 |
| 2720 | 544 | 2720 | 340 |

8个真实样例的计数倍率为1.595～1.600。更直观地看，adapter将tick除7200、episode_step除1440：旧数据中这两列基本相等；真实8tick环境中`episode_step_norm=0.625×tick_norm`。这不是最多350ms的后移误差，而是整局增长的特征关系差异。

RoPE位置本身由实际处理的逻辑帧递增，没有读取错误的旧header计数；矛盾来自显式header时钟，而非GQA的RoPE实现。

**影响边界：** 新BC训练和它的离线验证都看同一关系，因此仍可能正常降低离线loss；原生对战使用另一关系，才出现分布外输入。不能把它单独当作离线loss平台的解释。后续如对照修正，应版本化地统一观测适配规则或消除重复决策计数；不能静默改已训练checkpoint输入后宣称无代价修复。

## 2. 长程记忆存在，长程编码器信用分配受32帧限制

当前训练每个座位从开局读入，chunk32，每个chunk反向后调用`model.detach_state(state)`，整个座位完成才更新一次权重。缓存由同一版本权重生成，没有每chunk optimizer更新导致的stale-state混用。

CPU探针只对第64帧施加loss：

| 同一权重、同一64帧输入 | 结果 |
|---|---:|
| 全图与32帧detach版本的后半段最大forward误差 | 1.19e-6 |
| full BPTT对前32帧输入的梯度norm | 1.1258 |
| TBPTT对前32帧输入的梯度norm | **0** |
| TBPTT对后32帧输入的梯度norm | 6.1884 |
| 改动后32帧对前32帧输出的最大影响 | **0** |

因此“记忆保持整局”不能等同“晚动作可训练开局怎样编码”。当前query、写入和读出参数仍有当前chunk的学习信号，也能学读取历史缓存；不能把12.8秒误称为硬决策视野。

若样本需要很早的线索决定很晚的动作，长程编码器信用分配可能不足。该假设需要与更长TBPTT或辅助历史任务做计算预算匹配的对照。直接增加时序宽度没有改变这个边界。

## 3. KDA代数与初始门控未见整体故障

当前KDA明确使用逐key遗忘和delta residual写入，矩阵累积FP32；分块通过低三角求解实现。22项测试包含chunk与逐帧递推输出/状态/各输入梯度对照、mask、跨chunk完整梯度、257帧FP16投影、因果性、选择性reset和RoPE精度，全部通过。

初始化的`decay.bias=-4`，零输入坐标的保留率为`exp(-softplus(-4))=0.982014`，遗忘e-fold约55.1帧，即22.04秒。这不是“整局不忘”的初始KDA；但两层GQA仍缓存整局，不能只按KDA衰减认定整模型看不到早期。

随机32维探针的各层平均保留率约0.979，beta/read gate落在<0.01或>0.99的比例均0。**这个结果只排除了初始化结构必然饱和，未测当前训练权重是否饱和。** 实际183M应采样各层beta、read gate及retention分位数，并与异常loss/梯度样本对应。

实体编码器末端LayerNorm和时序RMSNorm会重新归一化，因此不能从原始buff达到1e5直接推断“KDA gate必然溢出/饱和”。输入坏尺度与记忆门控必须分别测量。

## 4. FP32保护没有消除实体汇总对大输入的敏感性

原审计确认旧492000行中存在`buff_ms`原值999999849，适配后99999.984375；17,509,845个buff时长标量中260个超过FP16有限范围。这个频率来自原始BC记录，不能直接当作重采样新集频率。

当前编码仍只是除10000；FP32帧路径避免溢出，但实体Transformer是prenorm residual，巨大初始投影仍可沿残差保留，随后pool attention直接使用这些实体token。其影响不只发生在最后LayerNorm输出幅度上。

在8个真实帧、固定旧已训练编码器上，仅给每帧一个有效实体的`buff_ms_1`注入已观察到的真实极值：

| 指标 | 原8帧 | buff压力 |
|---|---:|---:|
| 汇总输出是否有限 | 是 | 是 |
| 汇总向量平均norm | 15.95 | 15.96 |
| pool key平均norm | 54.71 | 12590.56 |
| pool归一化注意力熵 | 0.2226 | 0.0686 |
| 最大注意力概率>0.99的head/query比例 | 31.25% | 81.25% |
| 相同输出方向对实体x/y/hp输入的梯度norm | 12.7535 | 0.02933 |

最后一项约缩至原来的0.23%（约435倍差异）。这是固定随机输出方向的局部Jacobian探针，不是实际BC loss的梯度，也不是8个真实异常帧的频率估计。它证明“输出有限但信息敏感度退化”这条机制可以发生，**没有证明实际整体平台由这些稀有帧主导**。

## 5. 类别编号和实体关系表示仍有缺口

`queue`、`enemy_play_cast`仍没有加入card_fields/card_groups，原始最大ID约1416/1429直接进入header MLP；`ability_unit`是每局任意实体handle，仍作为连续数值。旧输入审计中这些不是仅出现几次的孤例，详见`BC_REAL_INPUT_AND_FIT_PROBE_20261110.md`。

8帧中header最大1429。将上述三类字段仅作诊断置零后，旧编码器pool query平均norm从108.45变为2.64，归一化注意力熵从0.223变为0.987。这确认它们强烈影响query；**注意力更均匀不等于策略更好，也不支持直接置零上线**。此前类别重编码64步对照没有超过原父模型初始控制集表现，仍需要更合适的迁移与数据验证。

实体`id`与`target`在adapter中清零，避免记住每局随机编号，但也没有显式保留“谁正在攻击谁”的关系。位置/方向/攻击状态能提供间接线索；不能据此断言任务完全不可观测。特别是header能力handle与实体ID之间没有直接join通路，值得单独检查而非将handle当连续强度。

WAIT/选牌主要依赖4个动态pool压成一个256维frame，再进入时序；落点头仍直接读取当前全实体token。扩到183M增加了时序容量，没有取消256维汇总瓶颈。此为待测表示限制，不能把所有空间信息都说成已经丢失。

## 建议下一次实际183M诊断记录

1. 在真实训练与控制轨迹上记录同口径分头目标、soft目标熵/超额KL及动作概率；不要把soft CE必须降到0作为验收。
2. 固定少量轨迹反复拟合，分组测frame、各KDA/GQA、WAIT/slot/tile的梯度norm与实际参数位移；与独立控制轨迹比较。若只改善训练，优先数据/泛化；若完全拟合不了，才继续分解优化/输入/容量。
3. 实际记录KDA retention/beta/read gate分位数和饱和比例，避免仅凭未训练小模型排除训练后的门控退化。
4. 将极端buff帧、普通帧按实际loss和裁剪前梯度分层，测其是否支配全座位梯度。不要把字段极值或单个反事实Jacobian直接宣称为主因。
5. 原生评估之前先统一或显式标注episode_step关系。域迁移与离线不收敛是两种问题，各自验收。

本审计没有修改生产模型或对当前云端100epoch训练作干预。
