# 本地 PPO 训练趋势复核与计划调整

范围：本地 `artifacts/ppo_v3_v100/metrics.jsonl`、`progress.jsonl`、`summary.json` 与现存验证目录。938条state_ppo日志按update保留最后一次记录，得到U1—929。最后checkpoint是U929，累计有效样本14,452,391，计数局数24,711。指标行没有墙钟时间，不能精确切出“昨天”的自然日；这里分析的是本地同步保存的训练轨迹，不代表刚查询过远端最新进程。

## 结论

不能把PPO loss没有持续下降叫作“不收敛”。PPO每轮更新采样策略、优势与对手，policy loss不具备BC固定数据交叉熵的解释。现有数据更符合“训练中有小幅学习，独立实战改善缺少验证”，而不是“完全不学”或“已证明架构不足”。

用户补充背景：已有较好的对BC胜率，因此没有继续加大BC对手权重；独立小批测试因方差大，后期有意转为traj胜率监控。此前把验证停用作为缺漏、提出优先增加BC比例的判断不完整，现已修订。traj对固定BC的足量计数是有效的进步证据；需要控制对阵分布与对手身份，区分跨更新窗口表现和某一冻结checkpoint的成绩。首轮保留60/25/15，用同配比的课程对照定位实战毛病，稀疏独立评估作复核。

训练胜率受对手采样、卡组和关卡分布影响，历史对手也在变化；不是固定外部验证。对BC 64.6%到66.0%的差别只有约1.4个百分点，不能据此宣布显著提升，68.1%到66.0%也不足以证明退化。anchor KL增大说明策略逐渐偏离BC，并不单独代表变差；需要外部结果判断这种偏离是否值得。

廉价出牌倾向值得专项检查，但这一窗口没有从“正常大牌”突然崩到“完全不出大牌”。高费请求比例也不能跨不同卡组当作唯一策略质量指标；当前计数是请求而非经确认的真实出牌。

## 数值与训练过程

- U698从25/30/45角色混合改为60/25/15；U709开始整局采样/BPTT；U711出现frame_microbatch=64。跨这些边界直接比较loss会混入训练语义变化。
- U9—697 Actor记录1350次overflow、19582次提交更新；按这两个计数估算跳过比例约6.45%。后期U709—800约1.81%，U801—864约0.76%，U865—929约0.58%。早期有训练效率损失，后期已大幅下降；未发现这些窗口中整轮Actor提交为0的记录。
- 初始logp最大偏差在U762/763约0.0651/0.0605，近期U865—929最大约0.000128，U929约0.000021。说明旧阶段有过一致性问题，但不能把旧问题认作最新行为差的唯一原因，也不能仅看最后一轮“零overflow”就概括整个训练过程。
- U929 EV约0.801是单轮数据；窗口中位数0.753更适合描述近期。EV针对保存的TD(lambda)目标，不证明长期价值、反打风险和私服场景都估计正确。

## 独立验证缺口与权重身份问题

现存独立验证仅U32/64/96/128，每对手40局。对BC分别52.5%/65.0%/42.5%/60.0%，其中U64/U128有延迟预算失败或子进程告警。这些不能证明U929最强，更不能把0.4秒端到端性能判断为全部通过。

额外发现：`best_validation.json`标注update64，而实际`actor_best_val.pt`内部update184。来源可能包含同步/旧元数据残留，尚未追溯到保存过程。必须按权重hash重新评估184，不能把U64的65%胜率贴到184模型上。上传包包含原文件及各自hash，未伪造两者关联。

## 对后续训练草案的调整

1. 首要工作改为权重身份与固定外部基线。用最新929、旧480/280、标注best的184和BC进行同条件筛查；不能预先宣称要回滚，也不能把最新当作best。
2. 保留原60/25/15，撤回默认提高BC至30%的建议。主要对照改为同一角色比例下是否加入定向课程；历史桶内的打法覆盖不足时再单独测试。近期训练中确实在赢BC，不能把自博弈一概认定为无效。
3. 专项课程仍合理：对局中制造需要防守、留解牌、攒组合和精确法术的情况，使用实际后续塔伤/交换/胜负验证；不奖励固定等待率或大牌率。重点解释“为何有输入反应却仍做出坏应对”。
4. 保持首轮架构、gamma/lambda、reward和熵系数一致。后期熵与anchor KL增加只是监测信号，暂不据此直接把tile entropy设0或提高BC约束；需要独立结果支持再做单变量实验。
5. 新分支以足量traj分层统计作为主要连续指标，记录固定BC身份、对阵权重、胜平负及行为计数；独立验证改为稀疏复核。比较等量有效决策，单种子短跑只用于筛查，复验后再使用更多CU。
6. 实机部署门控仍单独验收：贪心选牌已改为抽样，滚木几何已修，但火球门控尚未核验。不能靠PPO训练去补偿程序拦截，也不能把旧失败轨迹直接标成专家动作。
