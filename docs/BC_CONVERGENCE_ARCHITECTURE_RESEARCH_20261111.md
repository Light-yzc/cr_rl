# BC 收敛与架构：一手资料、可检验假说和实验顺序

日期：2026-11-11。本文只做代码与文献研究，没有运行 GPU、改动云端训练、安装依赖或保存模型副本。候选结构的参数/运算量是设计估算，不能当作本项目的学习效果或 L4 耗时实测。

当前最有依据的方向是先分清**优化/多目标冲突**和**空间读出的归纳偏置**，再决定是否扩大时序主干。优先比较相同起点的联合训练与落点单目标训练；空间结构优先考虑保留原头的、由卡牌和历史条件化的空间残差分支。GTrXL 有相关稳定性依据，但目前没有证据表明换掉整个 KDA/GQA 才能解决这里的落点问题。

## 已有证据约束了什么

本地冻结 step2274、183M 模型，对完整 293 局/586 座位作连续推理：

| 指标 | 175 局训练 | 53 局验证 | 65 局留出 |
|---|---:|---:|---:|
| 同口径总 loss，座位等权 | 6.6661 | 6.6666 | 6.6808 |
| 条件落点 CE | 5.0501 | 5.0118 | 5.0348 |
| 普通选牌准确率 | 47.26% | 45.25% | 46.34% |
| choice 时机 AUROC | 0.6988 | 0.6841 | 0.7018 |

整体 train→test loss 差的整局 bootstrap 区间跨零，不能继续把问题简单称为“训练记住了、验证全崩”。三边的落点都还弱。验证落点相对 train-only 牌种位置先验：alpha=.01 时模型差 .0532 nats，alpha=1 时模型好 .0885 nats；两档须一起报告，不能只挑一个基线。高费牌选择在验证/留出仅约29.4%，合法随机槽位约26%。这些事实支持定向实验，不证明整个模型容量不足。

## 现有空间头已经具备哪些能力

当前 `placement_logits` 用4×576个256维 query，加入卡槽、卡牌、历史 context 和空间 Fourier 特征，对当前实体 token 作 cross-attention；残差之后经共享逐位置 MLP 输出分数。实际诊断checkpoint的 **readout_version=2**，还已经包含投影/归一化空间特征、以卡牌和历史条件化的FiLM及空间门。它已经直接访问当前实体和坐标，不是只有一个全局向量，也不是没有 query 解码器。WAIT/选牌通过时序 context 输出，未使用同样的当前实体直接读出。

后续对32个冻结play帧的审计确认这条分支不是始终关闭：源空间门raw约0.04007、FiLM权重L2约4.526，空间附加项L2约占总query的9.19%。该比例只是所采样query的描述，不能仅凭“小于10%”判断影响不足；参见[fullhead结果](G:/Code/cr_rl/artifacts/bc_capacity_20261111/fullhead/results.json)的 `spatial_readout_initial`。

因此，下列两种说法都不成立：

- “再加入 Perceiver/query，就能补上现在缺少的实体读取”——这条路径已经存在。
- “只有换更大 Transformer 才能表达落点”——较大的主干无法自动提供局部参数共享、改善目标冲突或纠正输入契约。

## 空间候选一：query 解码的条件化与少量增容

[Perceiver IO 原文](https://arxiv.org/html/2107.14795)把输出 query 的语义与输出位置显式提供给解码器，再从 latent 中读出结构化结果；其作者[官方实现](https://github.com/google-deepmind/deepmind-research/blob/master/perceiver/perceiver.py)有独立的 `decoder_query`。这支持“输出需要明确的语义/位置条件”，不支持“任何 query 层都必然优于当前结构”。

本项目已经具备这些核心条件化构件，**不能把“首次加入FiLM/归一化query”列为这份checkpoint的新修复**。应该先审计其门值、FiLM权重和实际query贡献，再决定是否比较新的参数化。最小的可检验对照：

1. 保留已训练实体/时序和完整旧落点头。
2. 核查已存在的位置投影/归一化和 `(history context, card identity)` FiLM 的运行值；如果比较不同条件化参数化，必须明确与现有version2的结构差异，而非重复开启已有功能。
3. 或在现有256维逐位置特征后加一个零输出初始化的较宽残差 MLP，作为“最终读出是否不足”的容量对照。
4. 若最后 MLP 增容无收益，再比较完整 cross-attention/条件 query 的更新；不能把只训练最后 MLP 的负结果当作整个空间头的容量上限。

**假说与反证：**同等 play-label 暴露量及墙钟预算下，归一化条件化或残差读出能更快降低训练的 `CE−target entropy`，且独立验证也改善。若只有训练改善、验证退步，则发现的是过拟合能力，未证明有效表达更强。若 tile-only 可以学习、联合训练不行，则先排查优化干扰。

**成本：**本轮实际测试的是 `LayerNorm(256)→Linear(256,1024)→GELU→Linear(1024,1024)→GELU→Linear(1024,1)` 的深两层残差分支，新增 **1,314,305** 参数。其线性MAC约1.31M/位置，而旧128宽MLP约32.9k/位置；它又在4×576位置调用，因此不能用仅256→1024→1浅层的约26万参数或8倍估算来描述本轮候选。新分支可零输出初始化保留原函数；不要同时把输出层和唯一门都置零而造成分支无梯度。新增张量用新 readout 版本记录，只保留兼容权重，新增参数没有旧 Adam moments。

## 空间候选二：实体 scatter 到小棋盘，再用卡牌条件 CNN

[AlphaStar 正式论文](https://www.nature.com/articles/s41586-019-1724-z)的[官方补充材料](https://static-content.springer.com/esm/art%3A10.1038%2Fs41586-019-1724-z/MediaObjects/41586_2019_1724_MOESM2_ESM.zip)中 `Supplementary Information/detailed-architecture.txt` 给出：实体 embedding 投影后散射到地图；空间卷积保留 skip；location head 使用历史/动作条件的 gated residual blocks 与 FiLM，再产生空间 logits。这是明确的实体与空间通路结合，不是用 CNN 替代全部实体推理。更早的 [SC2LE 原始论文](https://arxiv.org/abs/1708.04782)也把空间输出作为游戏策略接口的重要组成。

适合当前18×32网格的候选：

```text
当前实体 token ──投影64通道──按可观察(x,y) scatter──共享小CNN──────┐
history context + card embedding ──FiLM/门控─────────────────────┤
绝对位置、合法区域、占用/计数 ──────────────────────────────────┤
                                                              ↓
                                                每卡576格残差logits
旧 cross-attention 落点 logits ────────────────────────加和→mask/softmax
```

建议从64通道、2个共享残差块＋1个卡牌条件残差块开始；若充分训练下确实欠拟合，再比较128通道或更多块。保留原头可避免把远程实体关系完全交给局部卷积。不是固定“保护石头人”或手工战术先验，空间权重由示范学习。

**可测假说：**目前每个位置 query 独立读实体，局部平移、邻近防守/法术覆盖等规律缺少直接的卷积参数共享。scatter+CNN 用更少示范学到空间组合，因而在相同卡牌的不同对局中改善落点 CE、2格内命中率，而非仅拟合常用地点。

**必须控制：**同格多实体不得覆盖丢失，应比较 sum/mean 加计数；可采用双线性 splat 保留亚格位置。边界、桥河与塔区域打破平移对称，需要坐标/合法 mask。敌我、实体形态仍来自已审计 token；不要把不可观察对手信息加入。scatter的像素量化、padding和混合精度累加也要作数值检查。

**估算成本：**64通道配置卷积约0.25G MAC/完整四卡帧；若四个残差块全部逐卡条件化，约0.68G MAC。128通道卷积主体约再×4。参数通常在约百万量级，具体取决于 FiLM 投影。当前2304query×200entities的两次 attention 乘法已约0.236G MAC，另有 query/output 投影与 MLP，因此 CNN 可能可行，但内核效率、FP32安全路径和数据搬运决定实际延迟，尚无新候选 L4 测量。

**迁移与判定：**旧模型+零输出空间残差是初始保守对照；比较 query 条件化与 CNN 时使用相同训练/验证卡组、标签权重和预算。单独冻结主干试读出，再端到端更新，回答的是两个不同问题。CNN若只提高训练拟合而没有 full53/65 改善，不晋级。

## 多目标：先测梯度，再决定 PCGrad / GradNorm

当前目标是加权 timing + conditional card + position，三个头共享实体/时序。它们的标签密度、分母和不可约熵不同；落点 loss 数值约5，时机约.43，**不意味着落点梯度一定占主导**。加一个与参数无关的常数能改变 loss 数值而完全不改变梯度，必须测实际梯度。

### 优先做的便宜诊断

在同一冻结 checkpoint 和固定对局上，对共享参数记录各任务的未裁剪梯度 norm、两两 cosine、三者加和后的 norm与clip比例。至少分别取最后共享时序块与实体编码器；仅在最后一层看到冲突不能代表全模型。使用真正有非WAIT/普通play的样本，不能把某chunk没有该任务标签时的零梯度混作“任务学会了”。

相同数据暴露下的 A/B：保存 Adam 的联合训练、重置 Adam 的联合训练、只用落点目标、然后必要时加权联合训练。若 tile-only 的训练明显改善而联合不改善，才增强了目标干扰的解释；如果 train 变好而独立验证变差，要保留过拟合解释。不同 Adam 初始状态和学习率都可能制造假因果。

### PCGrad 的适用范围

[PCGrad 原文](https://arxiv.org/html/2001.06782)在任务梯度内积为负时，对冲突梯度作投影。作者强调梯度冲突本身并不足以说明有害，梯度量级与曲率也有关；其理论结果有特定条件，并不是对本项目三目标、Adam、非凸时序网络的无条件收敛保证。

只有当上述测量与 tile-only 对照支持冲突时，才试 PCGrad。先限于共享参数，专属 head 保留本任务梯度；固定投影顺序随机种子。每任务分别反向/保留计算图通常增加训练成本，不改变推理成本。若给183M参数保存3份 FP32 task-gradient 向量，单这些向量已约2.19GB，常规 flatten/clone 实现峰值还会更多。应选取受控共享块或流式计算，不能默认把所有梯度额外复制几遍。

### GradNorm 的适用范围

[GradNorm 原文](https://arxiv.org/html/1711.02257)、[ICML/PMLR 正式页](https://proceedings.mlr.press/v80/chen18a.html)动态调整各任务权重，使选定共享层梯度 norm 接近由相对学习速度决定的目标。论文通常选最后共享层以降低成本；其特定视觉实验的约5%开销不能直接移植成这里的保证。

这需要稳定的任务损失参照。当前落点软标签有约2.4的熵底，timing又人为改变了类别先验，把三项原始 loss 相除得到“相对学习速度”未必表达我们要的目标。可以另外监控 `tile CE−target entropy`，但把这个量用于 GradNorm 是本项目新变体，必须独立比较。不要让动态平衡只降低重要任务权重，得到总 loss 下降而选牌/战斗变差的表象。

静态两三个权重的有界网格是更便宜的第一步；PCGrad/GradNorm 都不能修复少量高费示范、输入语义错误、标签延迟和闭环分布偏移。

## 序列：保留记忆与获得长梯度是两件事

本项目的 chunk32 对应12.8秒。每个chunk后 detach KDA矩阵与 GQA KV，因此较晚的 loss 不会直接反传训练较早chunk的记忆写入；前向仍能读取整局历史。不能将其叫“模型只能看12.8秒”。这个截断的偏置是已知问题，[Tallec/Ollivier 原文](https://arxiv.org/abs/1705.08209)研究了 TBPTT 梯度偏置与一种无偏估计方案，但并未证明该方案会在本项目更快。

优先做 chunk32/64 的同模型对照，固定总frame/play暴露、episode归一化和optimizer步数。区分外部TBPTT长度和KDA内部并行块大小：外部改64、内部仍32时，会保留两个32块的反向图，不会自动创建64×64的KDA块；若同时将内部块改64，其 `[time,time,key_dim]` 最大中间项才约×4。应分别记录这两个配置，不能只按激活×2估算。若仅因更大外部chunk减少Python调用/设备同步而提速，也应单独报告，避免称为长期依赖能力提升。

对于当前时刻的塔周围精确落点，直接空间通路未必需要很长梯度；若固定局面/已冻结特征的落点读出都拟合不好，先延长TBPTT或换时序核心不是最直接的诊断。

### KDA/GQA 与 GTrXL 的相关差异

[Kimi Linear 作者官方实现说明](https://github.com/MoonshotAI/Kimi-Linear)给出细粒度门控 delta记忆，并以3:1的 KDA/global MLA 混合。其长上下文吞吐、LLM训练规模和专用 FLA kernels 的结果，不能当作我们18×32策略的学习速度保证。本项目是普通PyTorch实现的6层KDA＋2层GQA，未复刻所有原始模块，也不是MLA。

[GTrXL 原文](https://arxiv.org/abs/1910.06764)的相关贡献是 pre-normalization/identity通路、GRU式深度门控和接近identity的初始化，以改善其RL任务中的优化；不仅是“保存state”。原文的 Transformer-XL memory 同样使用 stop-gradient，换 GTrXL 不会自动消除TBPTT偏置。本项目已有pre-RMSNorm残差，但没有同样的GRU式深度门控。

可分两级试验：

- **较小迁移试验：**保持KDA/GQA计算与权重，给残差更新增加版本化、接近identity的门控；原始输出初值与旧权重如何共存要先测试，不能任意改变缩放后叫同起点。
- **完整替换对照：**较浅512宽 GTrXL 或常规cached-attention作速度/可训练性基线；更少参数不是更弱表达的实证结论，也不是更强的保证。改变时序形状不能精确续旧Adam；两边必须采用可比较初始化/训练预算，不把“新模型重训”与“老模型短续训”混作架构优劣。

估算当前每座位6层KDA矩阵共约1.88MiB；2层、5 KV heads、64 head_dim、FP16的GQA在1200帧历史约2.93MiB，不含临时张量。六层512宽Transformer若缓存完整K/V，在1200帧约14.1MiB。这里缓存本身不是16GB RAM/显存的大头；主要训练工作量还包括宽FFN、实体编码、空间头和反向。任何新核心先在现有4090测，再在 L4 测，不引入额外大框架或权重下载。

## 一个可独立验证的提速点：只计算需要的卡槽落点

BC中真值普通出牌仅监督一个slot的条件落点，且 card 概率质量独立于归一化后的条件tile分布。现实现已跳过WAIT行的落点计算，但play行仍算四张卡的tile。实数数学上，改成只算真值slot可保留该BC目标。原头各query之间没有self-attention，所以推理还可先采card，再只生成已选card的tile。

**不能直接热更为“逐位相同”路径。** 本地head探针已经发现：CPU缩query形状的误差接近1e-7，而4090 TF32-high下conditional-logp最大偏差可到约.01069，门禁已拦截。形状变化会换GEMM/kernel，数学独立不等于混合精度重算一致。后续需比较FP32 highest/关闭TF32、不同实体量、batch与合法mask；明确区分BC近似容差与PPO采样/old_logp一致性要求，不通过放宽old_logp阈值掩盖差异。需要完整熵/KL的PPO路径仍保留完整分布。

即使验收通过，潜在约4倍只作用于落点头的一部分工作，不能称整训4倍。该优化应在结构候选确定后单独验收，避免混进当前因果A/B。

## 晋级标准：更快达到有效质量，而非每秒更多steps

首先用已固定的 [8/8/8完整对局cohort](G:/Code/cr_rl/artifacts/bc_capacity_20261111/cohort.json)筛选，不按结果重选样本。主比较同时保留：相同标签暴露量、相同墙钟预算、同一验证频率。缓存特征的head试验不等于端到端训练吞吐，也不能继承其速度数字。

| 阶段 | 比较 | 回答的问题 | 晋级条件 |
|---|---|---|---|
| 0 | savedAdam/freshAdam联合；tile-only | 慢学习是否有优化状态/多目标因素 | 有限且可重复，分头训练/控制集都报告 |
| 1 | 原读出/较宽残差读出/条件query | 最后读出与条件化是否受限 | 相同预算下独立集改善，不只训练拟合 |
| 2 | 胜者＋scatter64/CNN残差；必要时128 | 空间参数共享能否减少样本需求 | full53验证＋65留出、逐game对照CI及牌种/高费分层支持 |
| 3 | chunk32/64；门控残差；完整时序替换 | 更长梯度或不同记忆是否有价值 | 空间/目标因素控制后仍有独立收益 |
| 4 | L4完整推理及闭环旧BC/old对战 | 离线改善是否可部署、是否改善战力 | 延迟门禁通过；换边、固定种子、完整对局，无非法/故障 |

每个候选必须在L4测真实CPU适配→H2D→状态推进→采样→CPU动作返回，包含WAIT、普通牌、技能、满实体、开局及长历史、KV扩容边界。要求0.4秒内完成；沿用p99<300ms的余量目标并报告所有>400ms次数，至少两种并行座位数。先前旧结构压力夹具p99约28–36ms只证明旧候选有余量，不给任何新结构自动通行证；冷启动/网络/模拟器耗时应分开。

“表达最强”在这里应解释为：**满足L4延迟和资源约束的已测候选中，在独立对局/卡组及闭环评测上更好**。有限实验不能证明所有可能架构中的全局最优。
