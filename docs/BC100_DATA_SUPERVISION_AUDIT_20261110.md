# BC 数据与监督可学习性审计（2026-11-10）

本次只读审计293局原BC数据，并在内存中逐局复算事件保持的0.4秒离线监督映射。没有修改训练、模型、源数组或checkpoint，没有启动GPU、云实例或下载新数据。扫描ZIP成员时每次只保留一局观测/mask，进程采样RSS峰值约493MiB；没有展开14GB观测到磁盘。

## 主要结论

1. **未发现精确输入矛盾、非法标签进入当前监督或动作丢失。** 全数据20951条有效非WAIT在原数组中合法，并与native确认执行ledger一致。0.4离线映射保留21057条全部非WAIT，包括106条原flagged动作；这些flagged动作仍不参与监督。
2. **WAIT多数是有选择的WAIT，不能只靠去掉forced WAIT解决。** 训练有效180506行中，11752动作、168754 WAIT；其中147699是choice WAIT，21055才是forced WAIT。choice状态动作标签率约7.37%。但当前timing prior0.20已重新加权，不能把原始6.51%动作比例直接当成loss贡献比例。
3. **当前模型必须与廉价基线比较。** 固定16验证座位的train-only“牌种→落点边际”先验soft CE为4.8742或5.0311；合法常数时机基线为0.47582。若当前模型同口径tile CE约5.052、timing约0.49，它尚未稳定超过这些无战场条件的简单基线。这支持检查条件读出、优化和监督，不证明模型容量不足，也不证明数据完全不可学。
4. **独立战术监督有明显长尾。** 175训练局仅11248次普通出牌、504次技能；118张有出牌标签的卡中13张不足10次。石头人13、皇家巨人14、墓园17、凤凰3、X连弩3。不能把18万帧当成18万个独立策略示范。
5. **确有局部修复/时机不确定性和数值极值，但还不能归因整个平台期。** 训练有效动作中1161条相对原人类事件延迟至少0.25秒，247条超过1秒；直接手牌修复18、落点修复162。当前巨梯度step1911对应局中真实存在约100000的适配后buff时长。这些是可定位的风险，因果需要冻结权重对照。

## 时间对齐与WAIT边界

有效动作的逻辑后移为0～7 ticks，即0～350ms；p50为4 ticks，p95为7 ticks。原已执行BC动作间距足够，本次没有额外FIFO碰撞延迟。

所有307914个逻辑帧的源观测滞后为0～7 ticks，p50为2 ticks、p95为4 ticks。逻辑步长恒8 ticks，但保留的原观测相邻时间差为5～15 ticks，中位数10 ticks。模型看到的是原状态时钟与新的逻辑序列位置；不能把此描述为真实匀速推进后的战场。

训练choice WAIT中：

- 7646行距下一有效动作不超过8 ticks，约占choice WAIT的5.18%。
- 9734行距前后最近动作不超过8 ticks，约6.59%。
- 41894行距最近动作不超过20 ticks，约28.36%。

11248条训练play中11031条紧邻的上一逻辑帧是choice WAIT；其中9776对手牌相同，8921对legal mask相同。筛至手牌/mask/实体有效数量相同的4897对，移除显式clock列后的适配特征RMS中位数约0.00436；其中3226对RMS≤0.01。这个尺度仅为描述，不是语义距离，也不证明WAIT错标：精准出牌时机本来可能由很小的时间/位置变化决定。不能自动把法术标签扩成宽时间窗口。

## 精确输入重复与冲突

对307452个有效监督行做两类哈希：

1. 当前适配后header＋有效entity tokens＋当前legal mask。
2. 从对局开局至当前的完整因果适配输入前缀＋当前legal mask。

两类均未发现精确重复，因此也未发现相同完整输入对应不同标签的精确冲突。实体id/target已按真实adapter清零；屏蔽实体padding不参与hash。此结果只排除这种特定矛盾，不能证明标签绝对正确、模型学到的表示无混叠或重建状态与原人类状态一致。显式clock等字段也使完全一致输入较难出现。

## 独立标签、卡牌与卡组覆盖

训练118张卡共11248次有效普通出牌，覆盖129种物理卡组；验证113张/3847次，heldout100张/4955次。四个槽位训练标签为2735/2719/2881/2913，未见单槽支配。

训练出牌最常见为Princess568、IceSpirits542、GoblinBarrel522、Skeletons457、Log450。较稀少的核心/支援牌：Graveyard17、RoyalGiant14、Golem13、ArcherQueen9、Prince7、GoblinGiant4、Phoenix3、Xbow3。13张卡不足10条出牌。这里按原hand_card词表身份统计，进化/英雄形式仍通过slot/form特征表达，不把表中的实体词条数量当成独立卡牌数量。

训练≥5费有效出牌1665次，占11248次的14.80%。所以本轮BC数据并非没有高费正样本；但某些具体重型体系的示范仍非常稀少。

## 修复监督保真度

逐有效非WAIT行join原ledger的(simulator_tick, seat, executed_action)，全部20951行都有native_success=True的执行记录。训练11752条的修复/时差为：

| 指标 | 条数 | 占训练有效动作 |
|---|---:|---:|
| source→native提交延迟≥5ticks（0.25秒） | 1161 | 9.88% |
| source→native提交延迟>20ticks（1秒） | 247 | 2.10% |
| 直接手牌替换 | 18 | 0.15% |
| 首次手牌替换时刻及以后 | 434 | 3.69% |
| 直接落点修复 | 162 | 1.38% |
| 落点修复距离>2格 | 27 | 0.23% |

source→native延迟训练p50为3 ticks、p95为14 ticks、最大174 ticks（8.7秒）。该延迟是旧重建时对原人类事件的后移，与本次0.4逻辑映射额外0～7 ticks不同；固定20tick命令生效延迟也另是一项。

少量直接修复不能解释全部监督，而修复的后效应也不一定只持续一帧。没有原始arena真值可以证明某次修复后人类动作仍然战术最优。应做有界分层对照，不能凭“合法+native confirmed”宣布标签完全保真，也不能直接宣布全部数据无效。

## 与当前损失同口径的基线

固定16验证座位采用当前trainer顺序：原验证games `[5,13,15,23,33,37,54,58]`，每局seat0/1。各项均先按每seat求均值，再对16seat等权平均，与当前验证日志聚合一致；普通出牌总583条。

| 基线/下界 | fixed16 | 全53局验证 |
|---|---:|---:|
| 均匀合法nonWAIT类别NLL | 1.267470 | 1.299064 |
| 均匀合法普通卡槽准确率 | 32.413% | 31.298% |
| sigma1条件落点软目标熵 | 2.464013 | 2.424708 |
| 均匀真值卡槽合法tile CE | 5.569354 | 5.539951 |
| train-only牌种落点prior CE，alpha0.01/tile | 4.874172 | 4.958566 |
| train-only牌种落点prior CE，alpha1/tile | 5.031051 | 5.100330 |

牌种落点prior只在175训练局11248条出牌的sigma1高斯软目标上累计576格分布；验证按真值卡牌身份取分布，再按当前真实legal mask重归一。两档alpha在观察验证结果前固定并同时报告，没有选择验证最优值；没有把该prior写入模型。此基线使用真值卡槽，因此只比较条件落点项，不能拿它与端到端整动作准确率混比。

当前0.4验证全局动作先验q=4023/57493=0.069973736。timing target p=0.20时，固定16的常数p=0.20 CE为0.496119；若按真实legal mask在forced WAIT状态固定p=0、choice状态p=0.20，则CE为**0.475818**。简单H(0.20)=0.500402没有处理逐seat组成及forced mask，不是严格可比基线。

因此，若模型的同固定16 conditional tile CE≈5.052、timing≈0.49，不能仅凭总loss约6.7就说已学到明显场景决策；其条件落点/时机尚未稳定超过上述廉价基线。这里引用的模型值需由主审计与当前日志核对，不把旧阶段或其他验证集数值直接混用。
