# BC 验证读取修复（2026-11-04）

## 已确认的问题

Stage 2 原训练器 PID156041 在启动十余分钟后没有新优化步。`py-spy` 栈确认主线程仍在初始化自然验证，路径为 `evaluate -> build_bc_batch -> ShardArrayCache.read -> ZipExtFile`。一次观测中累计解压写盘已约174GB，GPU利用率为0%。进程仍活着不能等同于优化正在进行。

原读取器为访问少数历史帧，将整个 observations 数组解压到有容量上限的SSD缓存；自然验证和快速验证准备会再次遍历广泛分布的分片。扩大数据集后，验证的读取量与真正使用的样本量不匹配。

## 实现

新增 `src/cr_rl/data/validation_cache.py`，根据原有验证行和每个回放/座位的历史索引，收集精确需要的历史行；原验证行、128帧窗口、标签、合法动作mask和损失不变。

已有完整解压缓存时只拷贝选定行；缓存未命中时，在NPZ成员内按行前向读取，跳过的字节不写入磁盘。两个读取线程写入互不重叠的行。紧凑NPY保留全局行索引映射，只允许读取已声明的验证历史。

紧凑缓存绑定数据集SHA、验证行、历史行和窗口长度；完成后记录数组SHA，重用时校验。它只保存在Colab临时磁盘，不备份成新数据集。普通训练批次继续使用原来的分片缓存，训练采样和优化目标未改。

`train_bc.py` 的完整验证、自然验证和快速验证准备共同复用该紧凑缓存。先前每32步已准备好的快速验证CPU张量继续保留。

## 验证与边界

- Linux全量 **113 passed**；覆盖跨分片/双座位历史、配对mask索引、禁止整分片物化、缓存重用、越界拒绝、校验和损坏检测及只读校准不得修改训练缓存。
- 真实分片抽取16条历史、共1,330个独立历史行。两条路径的输入张量、121M模型的策略log-prob与value输出均逐项完全一致。
- 单次真实分片测量：旧路径写入768,372,736字节，选行路径写入37,548,032字节，紧凑文件37,367,808字节。首读耗时分别4.03秒和3.71秒。该单次结果不能外推为整轮训练速度；此前单次测量甚至是选行首读更慢，主要收益是缩小持久缓存和复用后续验证。
- 写盘统计使用 `/proc/self/io` 的 `write_bytes`，包含mmap脏页。`wchar` 不包含这类写入，不能用其约129字节的头部写入数代表实际I/O。
