# BC学习平台：代码、全量监督与真实183M模型诊断

## 结论与证据强度

**后续曲线更新：平台判断需要随新快照修正。** 再次只读网页实例日志到step3197（第9轮）后，完整第6/7/8轮固定验证loss为6.6397/6.5796/6.5741；第8轮中间2872点曾回升至6.6017，但末尾3056又创低。完整训练第7/8轮均值为6.5226/6.4858。当前是缓慢改善伴随局部反弹，**尚无持续验证恶化、训练继续下降的过拟合定论**；不能仅凭旧1822/2274快照就认定100轮不会收敛。下文实验仍用于解释学习限制，提出的修复应保持A/B候选身份，不因局部反弹直接改生产。

当前不是“模型完全不更新”。完整epoch2→4训练目标从6.7085→6.6293下降，当前权重在固定小训练集能明显提高拟合；真正需要解决的是**跨对局收益弱、场景条件落点尚未超过廉价先验、时机分辨率有限**。目前没有证据把主因归结为模型容量不够、KDA整体断图、FP16全部失效或LR仍在warmup。

这次完成了全293局监督扫描、实际合法mask基线、训练集拟合的牌种落点基线、当前183M checkpoint的64次局部拟合、实际KDA门控采样、冻结异常输入对照、固定16验证座位的概率排序/校准诊断。所有实验都在独立诊断目录；没有改正式模型、训练参数或云端进程。

仍未通过对照证明“只改某一项就能让完整验证/实战明显提升”。下文严格区分观察到的障碍、已证实的实现约束和待验证的修复。

## 1. 对齐当前训练阶段和指标

这是监督BC，reward、Critic EV、PPO KL早停或熵奖励不参与当前更新，不能套用旧PPO诊断。

- W&B只读快照：run `weidemingdeguge-test/cr-rl/impkv1lm`，最新step1916，epoch5；1310条连续训练更新。
- 独立模型实验：从已有网页L4只读流式取得step2274、progress epoch5/next_episode268的完整checkpoint，SHA `5944b51fcb0dd03ea4bf1680fe78a990e84024b59b2ef5fe50cd914d7abde2a7`。此进度字段表示已完成5轮、正在第6轮。
- 两个快照时间不同，不把step2274探针值冒充W&B step1822的验证值。
- 固定验证为8局×双座位=16座位，8731有效行。监控仍不是全53验证局，更不是实战胜率。
- soft落点CE包含Gaussian目标熵，理论下界不为0。按真实合法mask，固定16平均目标熵为2.4640；不能把“loss不归零”直接当作失败。

总目标仅改善约0.44%；中途step1656达到6.6588后又反弹。单条train loss来自不同对局座位，波动不能按同一小批次的拟合曲线解释。

## 2. 真正的条件学习收益还很弱

对原始293局只做训练/验证划分内统计；基线只用175训练局，验证标签未参与拟合。新0.4映射保留原pre-action mask和label，因此非WAIT基线可直接对齐。

| 固定16、同口径条件指标 | 低成本基线 | 当前W&B step1822 |
|---|---:|---:|
| 选牌NLL：合法非WAIT类均匀分布 | 1.2675 | 1.2173 |
| 普通槽位准确率：合法槽位均匀分布 | 32.41% | 46.97% |
| 落点soft CE：合法格均匀分布 | 5.5694 | 5.0519 |
| 落点soft CE：训练集每牌边际先验，alpha=.01 | **4.8742** | 5.0519 |
| 同上，预先固定alpha=1 | **5.0311** | 5.0519 |
| 落点soft CE理论下界：目标熵 | 2.4640 | 5.0519 |

选牌确实优于随机，不能说什么都没学到。到step2274复评，选牌NLL进一步到1.1729，领先合法均匀约0.0946，slot准确率49.16%；但落点soft CE反而到5.1173，仍没有超过只知道牌种、完全不读战场与历史的简单先验。选牌/时机改善被占比较大的落点项抵消，是当前总loss平台的直接分解；不是所有头都停住，也不是容量不足的证明。

soft CE5.0519与目标熵2.4640之差为2.5879，即仍有较大的超额KL。把6.7解释成“软标签所以已经到极限”同样不成立。

## 3. 实际183M能拟合小集，但控制集没有同步进步

RTX4090、已有Torch环境，step2274全模型/Adam恢复；FP16、frame32、chunk32、LR3e-5、clip1、原归一化和真实训练prior。训练仅原train replay252/112各seat0，两条不同validation replay5/13各seat0只作独立控制。每次完整座位后一次更新，两个训练座位轮流重复64次，不保存或发布训练后模型。

| 同固定cohort | 训练前 | 64次更新后 |
|---|---:|---:|
| 训练目标 | 6.9459 | **5.5834** |
| 训练条件选牌NLL | 1.3402 | **0.7183** |
| 训练条件选牌准确率 | 42.86% | **76.19%** |
| 训练落点soft CE | 5.1983 | **4.5451** |

训练目标下降19.6%，控制目标没有改善；控制落点距离从8.00变10.29。中途第32次更新的tile CE也明显反弹，优化并非完全平滑。

这是小cohort可拟合与迁移收益弱的直接证据，排除了“整个主干/动作头完全学不动”。它不证明所有训练对局都可拟合，也不自动等于当前全量训练已严重过拟合；两条控制轨迹仅用于定位，不作泛化统计结论。

模块梯度均非0：某代表更新preclip norm约heads3.02/frame0.783/temporal0.362。当前训练权重六层KDA的beta/read gate在此采样中没有<.01或>.99饱和；retention中位数约.980～.989，未见整体记忆门控失效。

## 4. 数据的独立监督量与时机困难

完整180506条训练有效行只有11248次普通出牌和504次技能，覆盖118张卡、129种物理卡组；其余为WAIT。13张牌不足10次示范，石头人13、皇家巨人14、墓园17、凤凰3、X连弩3。反复训练100轮不会新增这些独立战术示范。

168754条WAIT中，147699条是有动作可选的choice WAIT，21055条是forced WAIT；删forced不能解决多数时机区分。choice动作标签率约7.37%。原有prior0.20已对timing重新加权，card/tile又按ACT/PLAY单独归一化，所以不能说WAIT把所有头的梯度都淹没了。

真实近邻监督中，8921次出牌的前一个choice WAIT有相同legal mask；4897对还具有相同手牌/实体数量，3226对移除显式clock后的特征RMS差≤0.01。它们不是自动错标：法术/防守时机可能真的依赖微小变化。但说明粗略局面/时间统计容易学，精确WAIT→ACT边界更难学。

全307452有效行的适配后当前输入及完整因果前缀均未发现精确重复/冲突；合法动作和native执行确认一致。不能把平台期简单归咎于数据损坏或漏掉所有大牌。仍有旧重建时机不确定性：训练动作9.88%相对原人类事件延迟≥0.25秒、2.10%>1秒；直接手牌修复18、落点修复162。需要分层验证，不能把法术统一扩宽时间窗口。

## 5. 时机诊断不能只看0.5阈值召回

step2274原权重，只读推理固定16验证座位，所有帧推进state，forced WAIT单独剔除后：

- choice AUROC **0.6895**，随机为0.5。
- choice AP **0.1729**，同cohort类别基线约0.0788；时机排序确有学习，但远非很强。
- ACT标签平均出牌概率0.2962，choice WAIT标签平均0.2045，两个分布重叠较大。
- 阈值0.5：全行聚合召回11.35%、choice WAIT出牌判定2.27%；阈值0.2：召回68.07%、choice WAIT判定40.87%。这些是离线标签判定，不把所有替代动作都宣判为实战错误。

所以“低召回”不等于采样策略从不出牌。正式推理按概率随机采样；WAIT标签上的0.20概率也会产生出牌。单纯提高ACT/WAIT bias只能移动阈值，不能改善排序；在4条训练座位上选择的单一bias=-.25，冻结后验证weighted timing CE反而由.4454变.4489（全行口径），不支持仅靠一个全局偏置解题。

### 训练prior与推理概率还须明确区分

timing loss使用target prior .20，而自然训练动作比例q=.065105869；ACT与WAIT的权重比约3.59。若模型学到加权BCE最优解，其输出不是原数据的自然频率概率。理论关系为：

```text
logit(p_natural) = logit(p_weighted) + logit(q_train) - logit(0.20)
```

现有推理直接采样原joint概率，没有撤销这个prior权重。因此，确定性看起来偏WAIT与随机采样时更频繁出牌可能同时发生。自然概率校准、加权监督与真实策略目标必须分别验收；这不是“把WAIT偏置调大”的授权或实战收益证明。

step2274逐行应用理论逆变换（没有拟合validation、没有改权重），自然分布timing NLL由0.29570降至0.23175，choice WAIT的平均p(ACT)由0.20454降至0.07223，AUROC/AP不变；加权目标CE却由0.44543升到0.53555。它说明目标prior与自然概率是两种不同目标，不能同时按同一CE宣称改善。prior=.20是明确设置，**不能仅凭需要校准就称为无意的实现bug**；是否改变推理必须做冻结模型实战对照。

## 6. 长程梯度、输入语义与数值的具体问题

**长程梯度确实被切断。** 每chunk32、即12.8秒后detach全部KDA/GQA状态。前向整局历史仍在，当前query可学习读取历史；但晚期监督不能直接回传到更早chunk的encoder/key/value写入。CPU对照forward相同、被detach前输入梯度从1.1258变0。这是学习长程编码的限制，不是12.8秒硬决策视野。

**0.4训练与原生时钟有域差。** 离线映射改decision_ticks而保留原episode_step，原0.25步计数与真实0.4环境同tick计数相差约1.6倍。它可能影响实战，不能解释同分布离线验证本身为何不降。数据明确是离线增强，不能冒称native轨迹。

**异常输入存在，但本次未证实为主因。** step1911曾出现preclip norm38554，定位replay253 seat0；该局buff适配值约99999.99。当前邻近step2274冻结权重在该局原输入norm20.48；仅把近永久buff改成360秒的诊断对照norm21.45，loss6.3023→6.2817，没有消除梯度问题的证据。这不是step1910原权重的精确事故复现。

实际小编码器压力探针证明极值可造成注意力饱和和空间/血量敏感度下降，但频率与整体影响尚未证明。queue/cast类别编号、ability实体handle当连续输入也值得处理；直接清零/截断不是已验证修法。当前KDA实际门控采样正常，不能把输入大值直接推导成全时序层饱和。

**另有已复现的边界bug，尚无真实触发证据。** 聚合grad norm可能在每元素有限时溢出inf，现有GradScaler分支可能仍执行AdamW而不推进计数。真实当前日志没有此触发记录，所以不能拿它解释此次平台；后续工程修复应独立验收，避免混入策略对照。

## 7. 下一步应如何做

1. 优先把指标补齐：choice AUROC/AP、自然/加权时机概率、合法均匀/每牌落点prior、Gaussian超额KL，固定数据和统计口径。不要再用总体accuracy或总CE判断是否学会。
2. 下一次有限对照优先试**2～4条独立座位累积一次更新**，保持座位loss各自归一化后平均、同样的轨迹曝光数；比较原单座位更新的fixed validation和模块梯度。它是降低单局相关更新噪声的候选，尚未证明有效，不直接改生产。
3. 数据优先补少样本卡组和较高置信时机标签；对原时延/修复强度分层报告，保留法术精确时机。100轮只是预算，不能代替独立示范覆盖。
4. 输入语义和clock一致性作为单独版本修复。长程任务再做chunk32/64/128计算预算匹配对照；先不把更换GTrXL/再扩大模型当成结论。
5. 自然prior逆变换与原始加权策略分开做固定对战，判断真实策略目标；不根据离线阈值召回直接提高出牌概率。

如果要选一个最优先方向，当前证据支持**先处理跨局泛化/单局更新组织和有意义的监督基线**，不是继续扩参数。当前正式100epoch训练没有被本审计中断或热改。
