## 前一轮固定100局结果（历史）

`059d43a02138a34b1b3009cc2acc7630fb99a638` 的最小分片 `part-000051.parquet`。

| 模式 | 所有源事件均原生确认成功 | 长源子集完整 | 原生成功事件 |

## 剩余 65 局为什么没跑完

- **36 局模拟器提前决出胜负。** 后续人类事件还存在，但模拟器对局已经结束。
  原生 `match.decided()` 比 `vector.dones` 更早，后者要等待结算尾段。
  native card run code `4` 是 `match_over`，不是 submission 枚举中的开局冷却。
- **29 局技能不可用或无法唯一归因。** 21 局只有一个源候选，但当前模拟状态没有对应
  可用技能；8 局源候选有两个。3 次原生 `no_champion` 已按预算重试，仍不能成功。
- 这次没有因最终缺手牌或闭合法 mask 而截断的局。缺费等待、槽位 pending 和坐标
  修复能够处理的情况已经继续执行，没有加圣水或把未生效动作伪记为成功。

提前终局和技能目标消失说明战场状态已与人类源发生偏移。继续提高完整率需要更匹配的
规则/战斗模拟和可验证的技能归因。若将失败技能直接丢弃或终局后继续捏造状态，得到的
数字不能再使用本报告的“全部原始事件实际执行成功”定义。

## 已修复的执行与标签问题

1. 开局牌序搜索覆盖整个输入序列，保留候选歧义；运行时换手使用重排后的 native deck
   index，不再误用源卡组索引。换牌是手牌与队列的同牌集合交换，保留被换出的牌，保护
   pending/空槽，不改变时间、冷却或圣水。
2. 位置吸附在同一卡槽内寻找最近合法格，越界钳制也计入位移预算；时间使用下一个
   250ms 边界，保持同座 FIFO。失败动作可以在原始事件的截止预算内重新计算合法性。
3. 技能源读取 `ability_source_candidates`，处理 `card_key=null` / `coordinates=null`。
   多候选与实际 native champion 槽位共同匹配，只有一个合法槽位才执行。
4. 外部换手不写入普通 native replay，所以修复数据直接保存实际 **pre-action 状态、
   mask、动作**。不会先换手再重新 label 普通回放来生成另一套不一致的手牌状态。
5. `NativeReplayObserver` 按命令名关联源事件和真实执行结果，分开统计 submission 与
   confirmed。失败、未确认和人工 WAIT 尾部行被标记，保留为历史帧但不进入监督目标。
6. 输出可直接被现有 sharded BC loader 使用的 manifest；修复数据标为
   `dataset_kind=repaired`。独立实验可显式使用 `--allow-repaired`，不会被 exact A-tier
   的时长/数量门槛无限挡住，也不会被默认为原始人类状态数据。

## 扩展统计：repair 300 局（2026-11-09）

在相同源文件、相同 seed `20261109`、相同修复参数（开局牌序推断、无限手牌替换、最大落点吸附 50 格、最大延迟 200 tick）下，固定前 300 行重新运行，全部 300 行均有 attempt record，且使用已登记的 patched backend。

| 结果 | 局数 | 比例 |
|---|---:|---:|
| 所有源事件均原生确认 | 142/300 | 47.33% |
| 模拟器正常判胜负 | 212/300 | 70.67% |
| 两者联合可用 | 262/300 | 87.33% |
| 二者均未完成 | 38/300 | 12.67% |

交集为 92 局：142 + 212 - 92 = 262。严格源完成不能用联合率替代。300 局中 120 局在源末尾前正常结束，其中 92 局同时已经完成源事件，另 28 局只依靠正常终局口径；另有 43 局正常提前结束时仍有 pending 命令被屏蔽。剩余 38 局全部因 `ability_unavailable_or_ambiguous` 退出，没有模拟器 fault 或 timeout；其中原生重试仍留下 16 次 `no_champion`、1 次 `cooldown`。

这批结果说明联合口径已经超过 80%（87.33%），但严格可作为完整人类监督轨迹的比例只有 47.33%。因此 BC 可以使用 142 局严格完成样本；正常终局样本必须把终局后的源动作标为非监督，不能当作完整人类轨迹。
